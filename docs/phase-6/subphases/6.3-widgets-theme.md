## Port map (legacy web → trunk composites)

| Legacy (`legacy/apps/web/.../denali/fields/`)            | Trunk (`packages/workspaces/denali/src/composites/`)     |
| -------------------------------------------------------- | -------------------------------------------------------- |
| `denaliZodKindComponents.tsx` (zodKind → widget)         | `denali-composite-registry.ts` (`denali.*` renderer ids) |
| `denaliFieldRendererAnchors.ts` (anchor/dependent paths) | `denali-composite-anchors.ts`                            |
| `denaliZodKindAliases` (path overrides)                  | `DENALI_COMPOSITE_BY_CANONICAL_PATH`                     |
| Platform primitives (`text`/`enum`/…)                    | `platform-renderer-ids.ts`                               |
| `theme/tokens.css` (starter pattern)                     | `packages/workspaces/denali/theme/tokens.css`            |

## Scope

- Port composites/widget registry into `packages/workspaces/denali/src/composites/`
- `theme/tokens.css` — Phase 2 ingress contract (same as starter)
- **Renderer** implementations come from `platform-core` / `ui-primitives` — plugin registers **kinds**, not duplicate renderers in web

## Exit criteria

- All Denali field kinds map to platform renderer ids (no raw `<input>` in product wizard)
- Theme security: no arbitrary CSS injection — tokens file only
- Component/contract tests for widget registry resolution

## Forbidden

- Inline renderer copies from legacy web into `apps/web` without plugin registration
- platform-core PR that hard-codes `DENALI_*` widget kinds
