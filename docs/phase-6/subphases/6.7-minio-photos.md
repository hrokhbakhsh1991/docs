### Wizard upload error codes (API → web)

MinIO failures from `putDenaliWizardDraftPhoto` / `getDenaliTourPhotoSignedReadUrl` throw stable `Error.message` codes (`PHOTO_STORAGE_FULL`, `PHOTO_STORAGE_UNAVAILABLE`); `tour-wizard-photos.routes.ts` maps them via `mapWizardPhotoError` (same pattern as `mapBrandingError`).

| `code` | HTTP | When |
| ------ | ---- | ---- |
| `MINIO_NOT_CONFIGURED` | 503 | `MINIO_*` env incomplete |
| `PHOTO_STORAGE_FULL` | 507 | MinIO `XMinioStorageFull` (disk quota) |
| `PHOTO_STORAGE_UNAVAILABLE` | 503 | Connection / bucket / key errors |

The web BFF may wrap errors as `{ error: { code } }` or flat `{ code }`; `denali-photo-upload-client.ts` normalizes both. Wizard UI shows blob preview during upload (`URL.createObjectURL`) and signed-URL retry on thumbnail failure.
