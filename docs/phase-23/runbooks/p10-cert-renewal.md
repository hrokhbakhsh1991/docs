> **Scope:** Wildcard staging cert (Wave A) · optional on-demand TLS (Wave C).

---

## Preconditions

- Caddy installed (`install-caddy-profile-c.sh`)
- `/etc/caddy/caddy.env` generated by `render-caddy-env.sh`
- **Real** `PLATFORM_ROOT_DOMAIN` + DNS wildcard → VPS IP
- **Real** ACME email in `CADDY_ACME_EMAIL` (not `ops@example.com` — Let's Encrypt rejects example.com)

---

## Wildcard staging (Caddy automatic HTTPS)

### Monthly check (calendar)

```bash
set -a && source /etc/caddy/caddy.env && set +a
sudo caddy list-certificates | head -40
```

### Before expiry (30 days)

1. Confirm DNS still points to VPS: `dig +short operator.admin.${PLATFORM_ROOT_DOMAIN}`
2. Validate config:
   ```bash
   set -a && source /etc/caddy/caddy.env && set +a
   sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
   ```
3. Reload edge (zero-downtime):
   ```bash
   sudo systemctl reload caddy || sudo systemctl restart caddy
   ```
4. HTTPS smoke (from laptop):
   ```bash
   PLATFORM_ROOT_DOMAIN=your.apex CLUB_LABEL=operator pnpm run p10:profile-c-edge-smoke
   ```
5. Loopback regression (on VPS):
   ```bash
   ENV_DIR=/etc/app-tour-staging bash /opt/app-tour-staging/scripts/vps-deploy/smoke-four-process.sh
   ```

### Staging port note

`caddy.env` uses app `PORT=` values (e.g. staging `23000–23003`, prod `3000–3003`). Regenerate after port change:

```bash
ENV_DIR=/etc/app-tour-staging bash /opt/app-tour-staging/scripts/vps-deploy/render-caddy-env.sh
sudo systemctl reload caddy
```

## Failure playbook

| Symptom | Action |
| ------- | ------ |
| `invalidContact` / example.com email | Set `CADDY_ACME_EMAIL` to real mailbox in `caddy.env` |
| ACME rate limit | Pause on_demand; fix DNS; wait 1h |
| Wildcard not issued | Wildcard needs DNS-01 — configure DNS provider in Caddyfile or use non-wildcard hosts |
| 502 after renew | `smoke-four-process.sh` — apps must listen on ports in `caddy.env` |
| Caddy down | `journalctl -u caddy -n 50` · check `/var/log/caddy` permissions (`chown caddy:caddy`) |
