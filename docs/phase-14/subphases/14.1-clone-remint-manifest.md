# 14.1 — Clone remint manifest dispatch

## Charter

Mirror `wizardMedia` pattern for `POST /tours/clone-photo-remint` and neutral BFF path.

## Manifest block

```json
"wizardCloneRemint": {
  "module": "./photos",
  "workspaceTypeExport": "DENALI_WORKSPACE_TYPE",
  "executeRemintExport": "executeDenaliWizardPhotoRemintPlan",
  "assertDestKeyExport": "assertDenaliWizardDraftDestKey",
  "readConfigExport": "readMinioPhotoConfigFromEnv"
}
```

## Acceptance

- No `workspaceType !== "denali"` in `clone-photo-remint.routes.ts`
- No `getDenaliWorkspacePlugin` in `tour-clone-hydrate-logic.ts`
- `apply-denali-server-clone-photo-remint.ts` replaced by manifest-driven `apply-workspace-server-clone-photo-remint.ts`

## Server-side tour clone remint (post-create)

Optional manifest fields on `wizardCloneRemint`:

| Field | Purpose |
|-------|---------|
| `serverRemintModule` | Module exporting canonical remint planner (e.g. `./clone`) |
| `remintCanonicalExport` | `remintDenaliClonePhotosInCanonical` |
| `executeTourRemintExport` | `executeDenaliTourPhotoRemintPlan` (same photos module as wizard remint) |

`ToursService.cloneTour` calls `applyWorkspaceServerClonePhotoRemint` which resolves binding by `workspaceType` — no Denali gate in generic API layer.
