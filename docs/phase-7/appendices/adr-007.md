# ADR-007 — Second workspace proves platform genericity

```yaml
status: proposed
date: 2026-06-04
phase: 7
```

## Context

Phase 6 ports Denali as the first product workspace. Phase 7 must prove the plugin model is **generic** — a second minimal workspace (`urban`) without `platform-core` changes.

## Decision

1. **Urban = starter-plus** — slim field registry inspired by legacy `urban_event` **semantics**, not a Denali rail port.
2. **Genericity proof** — git baseline + `phase-7.contract.spec.ts` assert zero urban-only `platform-core` diff.
3. **Ops in generic layer** — observability (§10) and rate limits live in `apps/api` middleware, not urban branches.
4. **Silo opt-in** — `TenantConnectionRouter` in `tenant-kernel`; pool+RLS remains default.

## Consequences

- Legacy `urban_event → denali` wizard rail is **explicitly rejected** (see legacy `workspace-wizard.config.spec.ts` L11–13).
- Platform DoD closes at 7.9 with `ci:integrity` + forensic ≥ 8.

## Alternatives rejected

| Alternative              | Why rejected                     |
| ------------------------ | -------------------------------- |
| Urban as Denali-II port  | Violates DEC-P7-002; scope creep |
| Silo for all tenants     | Cost — enterprise opt-in only    |
| Urban-only observability | Violates DEC-P7-005              |
