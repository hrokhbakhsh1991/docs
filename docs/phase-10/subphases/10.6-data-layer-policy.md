## DEC-P10-006 — Schema ownership per workspace

```yaml
id: DEC-P10-006
status: LOCKED

```

### Decision

| Domain | Ownership | Table strategy (trunk R1) |
| ------ | --------- | ------------------------- |
| Urban registration intake | `@app-tour/workspace-urban` | Keep `UrbanRegistration` Prisma model — namespaced product table until generic `registrations` DEC in Phase 11+ |
| Denali finance / payments | `@app-tour/workspace-denali` | Keep `Payment*`, ledger outbox tables — denali-scoped; API hosts Prisma adapters only |
| Canonical tours | platform host | `Tour` + RLS — workspace-agnostic |
| Tenant registry / theme | platform host | `TenantRegistry` — `workspace_type` column binds manifest |

### Rationale

Renaming `UrbanRegistration` → generic `registrations` or splitting finance tables before plugin-host closure risks breaking Phase 8–9 urban/finance specs without user-facing gain. Host adapters (`configureUrbanHttpHost`, `configureDenaliFinanceHttpHost`) already isolate product SQL from `app.ts`.

### Consequences

- **P6-T02–T05** deferred until a workspace requests schema genericization.
- New workspaces with persistence add tables under `infra/sql/<workspace>_delta.sql` + Prisma models with workspace-prefixed names.
- RLS: new product tables follow `with-tenant-rls.ts` patterns from urban/finance deltas.
