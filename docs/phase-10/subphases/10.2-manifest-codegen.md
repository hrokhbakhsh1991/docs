## Guest catalog paths (PF-0 / Sprint 1)

Catalog list paths for marketing + portal BFF are **no longer hand-maintained** in `resolve-catalog-api-path.ts`. The generator reads each manifest's `httpRoutes` groups:

- List: `GET /{workspace}/catalog` (static handler)
- Detail base: inferred from `GET /{workspace}/catalog/:tourId` when present

Workspaces without catalog routes (e.g. starter) are omitted from `WORKSPACE_CATALOG_LIST_PATHS` — `resolveCatalogListApiPath` remains fail-closed (`UnknownCatalogPluginError`).

Regenerate after manifest `httpRoutes` change:

```bash
pnpm run generate:workspace-registry
pnpm run guard:workspace-registry-fresh
pnpm --filter @app-tour/workspace-sdk exec node --import tsx --test test/resolve-catalog-api-path.spec.ts
node --test scripts/test/workspace-registry-drop-in.spec.mjs
```

## Catalog registration flow (PF-0.3 / Sprint 2)

Portal public registration mounts workspace-specific flow surfaces and step components through `workspace-plugin-host`. The bootstrap file is **generated** from optional manifest block `catalogRegistrationFlow` (denali + urban only; starter omits it).

### Manifest shape

**Bundle mode** (denali — all steps owned by workspace):

```json
"catalogRegistrationFlow": {
  "surfaceExport": "denaliCatalogRegistrationFlowSurface",
  "steps": {
    "mode": "bundle",
    "export": "denaliRegistrationFlowSteps"
  }
}
```

**Compose mode** (urban — reuse platform auth steps + local intake/done):

```json
"catalogRegistrationFlow": {
  "surfaceExport": "urbanCatalogRegistrationFlowSurface",
  "steps": {
    "mode": "compose",
    "reuseAuthStepsFrom": "shared",
    "components": {
      "intake": "UrbanIntakeStep",
      "done": "UrbanDoneStep"
    }
  }
}
```

Auth steps (`phone`, `otp`, `profile`) live in `@app-tour/catalog-registration-flow-ui/react`. Optional manifest key `catalogRegistrationFlow.transportInitializerExport` codegen-wires transport hydration via `workspace-registration-transport-initializers.generated.ts` (Denali today; omit for urban/guest scaffold).

Every workspace with `httpRoutes` must set `"loadHandlersFromPackage": true` so `workspace-http-handler-loaders.generated.ts` lazy-imports handlers from `@app-tour/workspace-<id>/http`. Codegen admission: `assertHttpRoutesManifest()` (fails if flag missing). The API host must not keep product shims under `apps/api/src/urban/` — dispatch is manifest-only via `tryDispatchWorkspaceRoutes` (`guard-guest-api-shell.mjs`).

Regenerate after manifest change:

```bash
pnpm run generate:workspace-registry
pnpm run guard:workspace-registry-fresh
node --test scripts/test/workspace-registry-drop-in.spec.mjs
pnpm --filter @app-tour/catalog-registration-flow-ui run build
pnpm --filter @app-tour/workspace-plugin-host run build
```

Portal `next.config.ts` must list `@app-tour/catalog-registration-flow-ui` and `@app-tour/catalog-registration-auth` in `transpilePackages` (PF-1.5).

## Catalog presentation (PF-1.1 / Phase 1)

Marketing list/detail UI gates (`cityFilter`, section visibility) are **generated** from manifest block `catalogPresentation`. Required for every workspace with catalog `httpRoutes` (denali, urban).

```json
"catalogPresentation": {
  "listFeatures": { "cityFilter": true },
  "detailSections": {
    "difficulty": false,
    "fitness": false,
    "itinerary": false,
    "policies": false
  }
}
```

Outputs:

| File | Resolver |
| ---- | -------- |
| `packages/workspace-sdk/src/catalog/workspace-catalog-list-features.generated.ts` | `resolveCatalogListFeatures()` |
| `packages/workspace-sdk/src/catalog/workspace-catalog-detail-sections.generated.ts` | `resolveCatalogDetailSections()` |

Unknown `pluginId` → `UnknownCatalogPresentationPluginError` (`GUEST_CATALOG_PRESENTATION_NOT_CONFIGURED`). No silent `?? DEFAULT_*` fallback.

## Member profile capabilities (PF-2.1 / Phase 2)

Portal `/me/profile` field visibility comes from manifest block `memberProfile` (denali + urban). Workspaces without the block are omitted — `resolveMemberProfileCapabilities` is fail-closed (`MemberProfileNotConfiguredError`).

```json
"memberProfile": {
  "editableFields": ["nationalId", "fatherName", "birthDate"],
  "readOnlyFields": ["displayName"],
  "sections": [
    { "id": "participant", "fields": ["nationalId", "fatherName", "birthDate"] }
  ]
}
```

Output: `packages/workspace-sdk/src/profile/workspace-member-profile-capabilities.generated.ts`

Validators are attached at runtime from `member-profile-validators.ts` by field id (not manifest-emitted functions).

Guest conformance levels extend to **L3** when `memberProfile` + `catalogRegistrationFlow` + catalog routes are all present.

## Guest extension schema admission (PF-1.8)

Guest-facing manifest extensions are versioned. Every workspace with catalog `httpRoutes` must declare:

```json
"guestExtensionsVersion": 1
```

Authority:

| Artifact | Role |
| -------- | ---- |
| [`docs/dev/workspace-guest-extensions.schema.json`](../../dev/workspace-guest-extensions.schema.json) | JSON Schema for guest blocks |
| `assertGuestExtensionsManifest()` in `scripts/generate-workspace-registry.mjs` | Runs **before** any `*.generated.ts` emit |
| `scripts/guards/guard-guest-extension-schema.mjs` | CI guard — schema + admission parity |
| [`docs/dev/adr-guest-plugin/`](../../dev/adr-guest-plugin/) | ADR-GP-001 (flow union), ADR-GP-002 (schema admission), ADR-GP-003 (`workspace:create --guest`) |

Admission failures (codegen abort):

- Missing or wrong `guestExtensionsVersion`
- Malformed `guestThemeStylesheets`, `catalogPresentation`, `catalogRegistrationFlow`, or `memberProfile`
- Invalid flow union (`mode: "bundle"` vs `"compose"` + `reuseAuthStepsFrom`)

Workspaces without catalog routes (e.g. starter) omit `guestExtensionsVersion` — not subject to guest extension admission.

Regenerate + verify:

```bash
pnpm run generate:workspace-registry
pnpm run guard:guest-extension-schema   # or full bundle:
pnpm run guard:guest-plugin-conformance
```

## Guest workspace scaffold (PF-3)

`pnpm run workspace:create -- <id> --guest` emits an L3-valid `workspace.manifest.json` plus minimal package stubs (see [10.7 — Guest workspace scaffold](./10.7-enforcement-dx.md#guest-workspace-scaffold-guest-pf-3)). After scaffold:
