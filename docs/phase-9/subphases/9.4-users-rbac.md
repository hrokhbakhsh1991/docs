## 1. Behavioral Objective

Port legacy **users directory + invites** with **locked 3-tier RBAC** per DEC-P9-015 — **not** legacy five-role persistence.

| Capability                  | Detail                                                                          |
| --------------------------- | ------------------------------------------------------------------------------- |
| User directory              | List active members — paginated, tenant-scoped, infinite scroll                 |
| Search + sort + role filter | URL-synced (`search`, `role`, `sort`) — roles: **all · owner · admin · member** |
| Pending invites             | Create, revoke, resend                                                          |
| Invite accept               | `/auth/invite/[token]` flow                                                     |
| Role change                 | Owner → admin/member · Admin → member · **no owner grant via PATCH**            |
| CSV export                  | Client-side export of filtered roster                                           |
| Remove member               | `DELETE /users/{id}` — owner/admin; cannot remove self or owner                 |
| User rewards modal          | Rewards read/update — admin/owner only                                          |
| RBAC                        | Denali: `isAdminOrOwner` for directory + mutate · Member → **403** + locked UI  |
| Legacy hydrate              | `leader` → `admin` · `viewer` → `member` at membership hydrate                  |

**Stack lock (DEC-P9-013):** Phase 2 primitives + CSS Modules — see USERS-DIRECTORY-UX §6.
