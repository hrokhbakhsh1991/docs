# 12.3 — Publish field gate + edit draft autosave

> **Status:** DONE — 2026-06-11  
> **Parent:** Phase 12 enterprise closure  
> **Prerequisite:** [12.2b edit-preset-patch](12.2b-edit-preset-patch.md)

## Problem

After 12.2b:

1. **Denali PATCH** has no publish-field owner gate — admin can flip `publishStatus` via wizard review (Urban has `urban.tour.publish_fields` since Phase 8.1).
2. **Edit wizard** keeps draft in React state only — browser refresh loses work; create flow already has workspace draft sync.

## Solution

| Deliverable | Mechanism |
|-------------|-----------|
| Denali publish gate | `tourWrite` manifest binding → `denaliTourPatchRequiresOwner` |
| Owner surface | `denali.tour.publish_fields` — workspace owner only (mirrors Urban) |
| PATCH merge | `mergeDenaliCanonicalPatchData` — shallow root merge for flat Denali canonical |
| Edit autosave | `denaliEditTourDraftKey(tourId)` + `useWorkspaceDraft` on edit wizard |

> **Correction (2026-06-11):** Edit autosave on wizard client was **removed** with edit-wizard revert; **restored on flat edit** after [12.4](12.4-denali-flat-edit-form.md) (12.4d).

### Protected publish paths (Denali)

```typescript
["publishStatus", "basicInfo.publishStatus"]
```

Detection matches flat `data.publishStatus` or nested `basicInfo.publishStatus` in PATCH body (same semantics as wizard submit artifact).

### Edit draft key

```typescript
denaliEditTourDraftKey("tour-uuid") → "denali-edit:tour-uuid"
```

Same namespace as create (`operator.wizard`), distinct key per tour id.

## API insertion

`handlePatchTour` already calls `tourPatchTouchesProtectedPublishFields` + `tourPublishFieldOwnerSurface` via generated bindings. Adding Denali to `WORKSPACE_TOUR_WRITE_BINDINGS` activates the gate without route fork.

Owner assert uses `assertDenaliWorkspaceOwner` (Denali package) parallel to Urban's `assertWorkspaceOwner`.
