# 12.1b — Composite field registry + host denali branch removal

> **Status:** DONE — 2026-06-11  
> **Parent:** [12.1 legacy-parity-closure](12.1-legacy-parity-closure.md)

## Problem

After 12.1, `WorkspaceWizardHost` and `WizardField` still branch on `pluginId === "denali"` for:

- rules module load fallback
- matrix dimension fallback
- composite widget render
- field label namespace

Denali hooks already implement the generic path — fallbacks duplicate workspace logic in web.

## Solution

| Deliverable | Mechanism |
|-------------|-----------|
| Composite render | `compositeSurfaceId` on `WorkspaceWizardHostHooks` + `wizard-composite-surface-registry.tsx` |
| Field labels | `fieldLabelSurfaceId` on hooks + same registry |
| Host cleanup | Rules/dimensions **hooks-only** — no `loadDenaliWizardRulesModule` / `resolveDenaliDimensionsFromDraft` in host |

## Hook additions (SDK)

```typescript
readonly compositeSurfaceId?: string;
readonly fieldLabelSurfaceId?: string;
```

Denali reference: both `"denali"`.

## Acceptance

| ID | Assertion |
|----|-----------|
| SDK-12.1b-01 | `compositeSurfaceId` + `fieldLabelSurfaceId` on hooks type |
| WEB-12.1b-01 | `rg 'pluginId === \"denali\"' workspace-wizard-host.tsx` → **0** |
| WEB-12.1b-02 | `rg 'pluginId === \"denali\"' wizard-field.tsx` → **0** |
| WEB-12.1b-03 | Denali wizard unit specs green |
