# 12.0 — Workspace wizard host hooks (SDK)

> **DEC:** DEC-P12-001 (draft)  
> **Status:** IN PROGRESS — 2026-06-11  
> **Roadmap:** TEMP `denali-wizard-enterprise-roadmap.md` Phase 1

## Problem

`WorkspaceWizardHost` (`apps/web/src/wizard/workspace-wizard-host.tsx`) branches on `pluginId === "denali"` for:

- rules module load
- matrix dimensions from draft
- contextual field rules
- per-step validation
- review step id
- completion header

This blocks workspace #2 and violates MAP §3 (workspace plugin owns business rules).

## Solution

Optional **`WorkspaceWizardHostHooks`** on `WorkspacePlugin`:

```typescript
interface WorkspacePlugin {
  // …existing fields…
  readonly wizardHost?: WorkspaceWizardHostHooks;
}
```

Host reads hooks from the loaded plugin — Denali is the first implementer.

## Hook surface (v1)

| Hook | Purpose |
|------|---------|
| `reviewStepId` | Reserved review/read-back step (Denali: `"review"`) |
| `showCompletionHeader` | Quality/completion meter above stepper |
| `usesContextualFieldRules` | Second-layer visibility after matrix plan |
| `usesStepValidation` | Block Next until step-scoped validate passes |
| `loadRulesModule()` | Lazy workspace rules (Denali: evaluateFormFieldRule bundle) |
| `resolveMatrixDimensionsFromDraft(draft, rules)` | Dynamic matrix cell (Denali: category×duration from tour kind) |

**Deferred to 12.0 follow-up:** `applyContextualFieldRules`, `validateDraftSync`, `prepareSubmitPayload`, composite registry — still in web until form adapter moves to denali package.

**Engine ingress:** `wizardHost` contains functions — strip via `pluginForWizardEngine` before `PlatformWizardEngine.create` (same as `tourClone`).
