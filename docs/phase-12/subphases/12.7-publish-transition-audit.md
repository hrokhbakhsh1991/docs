# 12.7 — Publish transition audit trail

> **Status:** DONE — 2026-06-11  
> **Prerequisite:** [12.6 publish readiness](12.6-publish-readiness-validation.md) · [12.3 publish gate](12.3-enterprise-publish-edit-autosave.md)

## Problem

PATCH `/tours/{id}` always wrote `TOUR_UPDATED` in the forensic audit log. Owner **publish** / **unpublish** transitions (`publishStatus` draft ↔ active) were not distinguishable for compliance or operator forensics.

## Solution

| Layer | Mechanism |
|-------|-----------|
| Denali detector | `detectDenaliTourPublishTransition` — flat or `basicInfo.publishStatus` |
| API dispatcher | `detectTourPublishTransition(workspaceType, before, after)` — Denali + Urban |
| Atomic TX | After `TOUR_UPDATED`, append `TOUR_PUBLISHED` or `TOUR_UNPUBLISHED` in same TX |
| Metadata | Allowlisted `fromPublishStatus` / `toPublishStatus` on transition rows (Denali) |

```text
PATCH merge → validate → persistTourUpdateAtomically
  ├─ audit: TOUR_UPDATED (always)
  └─ when publishStatus transitions:
       audit: TOUR_PUBLISHED | TOUR_UNPUBLISHED (+ status metadata)
```

Non-forensic (`STORAGE_DRIVER=memory`) path unchanged — no audit rows.

## Acceptance

| ID | Assertion |
|----|-----------|
| DEN-12.7-01 | Denali detector reads flat + nested publishStatus |
| DEN-12.7-02 | draft→active = `published`; active→draft = `unpublished` |
| API-12.7-01 | Denali workspace dispatch detects publish transition |
| API-12.7-02 | Urban workspace dispatch detects publish transition |
