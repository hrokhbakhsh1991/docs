# 12.8 — Urban / Starter platform wizard host hooks

> **Status:** DONE — 2026-06-11  
> **Prerequisite:** [12.0 wizard plugin hooks](12.0-wizard-plugin-hooks.md)

## Problem

Only Denali attached `WorkspacePlugin.wizardHost`. Urban and Starter used implicit host fallbacks in `WorkspaceWizardHost`, so multi-workspace parity was not explicit on the plugin contract.

## Solution

| Workspace | `wizardHost` source |
|-----------|---------------------|
| Denali | Custom `denaliWizardHostHooks` (rules, contextual, submit, publish readiness) |
| Urban | `createPlatformWizardHostHooks({ dimensions: { tourType: "city" } })` on `urban.plugin.ts` |
| Starter | Same factory on `workspace-starter` wrapper (`starter.plugin.ts`) — SDK reference stays hook-free to avoid `workspace-sdk` ↔ `platform-core` cycle |

Factory lives in **`@app-tour/platform-core`** (`createPlatformWizardHostHooks`) because it delegates to `PlatformWizardEngine.validateCanonical`. Return type is `WorkspaceWizardHostHooks` from workspace-sdk.

Factory behavior:

- `usesStepValidation: true`
- `resolveMatrixDimensionsFromDraft` → fixed matrix cell
- `validateDraftSync` → engine validation on draft envelope (strips `wizardHost` before engine init to avoid recursion)

Denali remains the reference for advanced hooks; Urban/Starter prove the host runs without `pluginId === "denali"` branches for validation/dimensions.

`PlatformWizardEngine.create` strips `wizardHost` (and other function-bearing plugin surfaces) before workspace-sdk ingress — same pattern as Denali `denaliPluginForWizardEngine`.

## Acceptance

| ID | Assertion |
|----|-----------|
| PC-12.8-01 | `createPlatformWizardHostHooks` exported from `@app-tour/platform-core` |
| URB-12.8-01 | Urban plugin exposes non-empty `wizardHost.validateDraftSync` |
| STR-12.8-01 | Starter plugin exposes non-empty `wizardHost.validateDraftSync` |
