> **Implementation SoT:** [`../appendices/IMPLEMENTATION-DECISIONS.md`](../appendices/IMPLEMENTATION-DECISIONS.md) **DEC-003** — projections are **columns on `tours`**, not a separate table.  
> **Unified TX (5.4-S1):** [`atomic-canonical-tour-persist.ts`](../../../apps/api/src/canonical/atomic-canonical-tour-persist.ts) — `tx.tour.create` includes `title` + `schema_version` in the **same** transaction as `tx.outboxEvent.create`.

## Projection model (repo truth)

| JSON path           | DB column              | Prisma field         |
| ------------------- | ---------------------- | -------------------- |
| `data.basics.title` | `tours.title`          | `Tour.title`         |
| `schemaVersion`     | `tours.schema_version` | `Tour.schemaVersion` |

**There is no `tour_projection` table.** Docs that refer to `tx.tourProjection.update` mean **updating projection columns on the tour row** via `tx.tour.create` / `tx.tour.update`.

## Downstream projection failure (partial success)

Sync columns on `tours` are written in the **same TX** as canonical create (RULE-008). Async read-models that subscribe via `subscribeIdempotentDomainEvent` may still fail **after** the relay marks outbox `done` and the handler claims `processed_domain_events`.

| Symptom                                                           | Meaning                                                  |
| ----------------------------------------------------------------- | -------------------------------------------------------- |
| `tours` row + outbox `done`                                       | Canonical path succeeded                                 |
| `processed_domain_events` row                                     | Handler claimed; replay will **not** re-run side effects |
| `projection.inconsistency` log + `projection_inconsistency_total` | Downstream failed — **manual reconciliation** (DEC-008)  |

**Ops:** grep logs for `event=projection.inconsistency` or scrape `projection_inconsistency_total`; correlate `domainEventId` with outbox row. Spec: [`saga-rollback.spec.ts`](../../../apps/api/test/4-integration/saga-rollback.spec.ts).
