## Enterprise standard (2026 pattern)

Production multi-tenant SaaS separates **tenant administration** (`admin` can operate members, generic documents) from **workspace ownership** (configuration mutations on product-specific surfaces). Authorization is evaluated **synchronously at the API boundary** before handler body and rate-limit budget consumption. BFF/web layers call the same `TenantAuthz` contract — no parallel `role === "owner"` string gates in UI components.

## Resilience vector — Single-Owner authentication

### Threat: compromised `role=admin` on urban tenant

| Without `isWorkspaceOwner` isolation                                     | With 8.1 isolation                                                                   |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| `isAdminOrOwner` → **true** for admin                                    | `isWorkspaceOwner` → **false** for admin                                             |
| Admin reaches `PATCH /urban/settings` if generic `canManageTenant` leaks | `assertWorkspaceOwner` → `UrbanOwnerRequiredError` at step ④                         |
| Lateral escalation: theme JSON, publish, catalog admin                   | **Contained** — admin retains generic tour draft edits only (matrix § Catalog admin) |

### Control chain (fail-closed)

```text
compromised admin bearer
  → ① resolveTenantContextFromRequest (valid admin context)
  → ② workspaceType = urban
  → ③ buildTenantAuthz → canPerformUrbanOwnerMutation(..., urban.settings.update)
  → isWorkspaceOwner(parsed) === false
  → ④ assertWorkspaceOwner throws UrbanOwnerRequiredError
  → ④b error-interceptor → HTTP 403 { code: URBAN_OWNER_REQUIRED, correlationId }
  → ⑤ runWithHttpRequestContext NEVER entered — no persist, no outbox, no rate-limit write debit
```

### Web parallel path

```text
compromised admin session on /settings/urban
  → canLoadUrbanSettings({ authz, ... })
  → authz.canPerformUrbanOwnerMutation(...) === false
  → WizardAccessDenied (data-workspace-wizard-forbidden, data-status-code=403)
  → no settings form fields rendered — no client-side PATCH surface
```

**Escalation prevented surfaces (URBAN_OWNER_SURFACE_ALLOWLIST):** `urban.settings.*`, `urban.catalog.admin.*`, `urban.catalog.publish|unpublish`, `urban.tour.publish_fields` — see CASL-URBAN-OWNER-SPEC § `TenantAuthz` extension.

## Blast radius assessment — `assertWorkspaceOwner` failure modes

### Boundary definition

| Zone                 | Inside blast radius                                                                                      | Outside blast radius                                        |
| -------------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **API owner routes** | `GET/PATCH /urban/settings`, `GET/PATCH/DELETE /urban/admin/catalog*`, `POST /urban/catalog/{id}/publish | unpublish`, urban `PATCH /tours/{id}` with publish fields   | `GET /urban/catalog*`, `POST /urban/registrations` (public — no `assertWorkspaceOwner`) |
| **Web**              | `/settings/urban` RSC + server actions calling owner APIs                                                | `/catalog/**` public pages                                  |
| **Data**             | `tenants.theme.urban` JSON, `publishStatus` mutations, catalog admin rows                                | Published catalog reads, `urban_registrations` intake (8.2) |

### Failure mode matrix

| Failure locus                                                         | Symptom                    | HTTP / UI outcome                                                               | Data mutation | Compliance signal                                                                          |
| --------------------------------------------------------------------- | -------------------------- | ------------------------------------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------ |
| **F-8.1-A** `resolveTenantContextFromRequest` throws / null auth      | Missing/invalid bearer     | **401** via tenant-kernel (before assert)                                       | **None**      | `event=tenant.auth.missing` (existing)                                                     |
| **F-8.1-B** `resolveWorkspaceTypeForTenant` errors                    | Cannot classify tenant     | **403** or **500** — handler must not default to `starter` grants on urban host | **None**      | `event=urban.workspace_type.resolve_failed`                                                |
| **F-8.1-C** `buildTenantAuthz` throws (malformed `TenantAuthContext`) | Authz construction failure | **403** `URBAN_OWNER_REQUIRED` if mapped; else **500** — **never 200**          | **None**      | `event=urban.authz.build_failed`                                                           |
| **F-8.1-D** `assertWorkspaceOwner` deny (admin/member/anon)           | Expected control           | **403** `{ code: URBAN_OWNER_REQUIRED, correlationId }`                         | **None**      | `urban_owner_required_total{surface}` (8.5 metric; log `code=URBAN_OWNER_REQUIRED` in 8.1) |
| **F-8.1-E** `assertWorkspaceOwner` uncaught bug                       | Regression                 | **500** via error-interceptor — still **no** handler body                       | **None**      | Pager: `FAIL` on `urban-settings-patch.spec.ts`                                            |
| **F-8.1-F** Web `canLoadUrbanSettings` false                          | Member/admin session       | **403 UI** `[data-workspace-wizard-forbidden]`                                  | **None**      | No API owner call issued                                                                   |

### Degraded infrastructure — Redis session store unreachable

**Scope note:** 8.1 owner gate does **not** read Redis. Session resolution occurs in ① `resolveTenantContextFromRequest` (JWT verify / dev bearer per `auth-env.ts`). Redis (`REDIS_URL`) backs **rate limiting inside ⑤** `runWithHttpRequestContext`, which runs **only after** successful owner assertion on owner routes.

| Scenario                                           | Owner route behavior                                       | Fallback state                                                                                                          |
| -------------------------------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Redis down **before** ④ pass                       | N/A — owner routes never reach rate limiter if denied at ④ | **403** `URBAN_OWNER_REQUIRED` for non-owners (unchanged)                                                               |
| Redis down **after** ④ pass (owner actor)          | `TENANT_RATE_LIMIT_REDIS_FAILURE_POLICY=closed`            | **503** `RATE_LIMITER_REDIS_UNAVAILABLE` — **no** settings persist (fail-closed per `redis-rate-limiter-resilience.ts`) |
| Redis down on **public** routes (out of 8.1 scope) | Rate limiter open/closed per env                           | Documented in [`env-runtime-matrix.md`](../env-runtime-matrix.md)                                                       |

**Session store rule for 8.1 implementation:** If a future Redis-backed web session store is introduced for urban settings, **unreachable store = treat as unauthenticated for owner surfaces** → web `canLoadUrbanSettings` returns **false** → `WizardAccessDenied` (**403**). **No** cached admin session may bypass `canPerformUrbanOwnerMutation`.

### Degraded infrastructure — CASL / TenantAuthz capability path unreachable

8.1 does **not** ship a distributed CASL capability cache. Authorization is **in-process**:

```text
buildTenantAuthz(auth) → canPerformUrbanOwnerMutation(tenantId, surface, workspaceType)
```

| Scenario                                                 | Required behavior                                                                                                                                                  |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `buildTenantAuthz` throws                                | **Deny** — do not invoke handler; map to **403** `URBAN_OWNER_REQUIRED` when `workspaceType=urban` and route is owner-only; never fall through to `isAdminOrOwner` |
| Web cannot construct `TenantAuthz` (SSR context missing) | `canLoadUrbanSettings` → **false** → **403 UI**                                                                                                                    |
| Hypothetical future ability cache miss/timeout           | **Total deny** — return **403** `URBAN_OWNER_REQUIRED`; increment `urban.authz.cache_unreachable_total`; **no** stale ALLOW                                        |

### Compliance alert contract (immediate)

On any degraded authz path (**F-8.1-B**, **F-8.1-C**, cache unreachable):

```json
{
  "event": "urban.authz.compliance_alert",
  "severity": "P1",
  "surface": "<UrbanOwnerSurface>",
  "tenantId": "<uuid>",
  "correlationId": "<requestId>",
  "action": "DENY_FAIL_CLOSED",
  "httpStatus": 403,
  "code": "URBAN_OWNER_REQUIRED"
}
```

Emit via structured logger in `handleHttpError` / `assertWorkspaceOwner` catch boundary — **before** response flush. Pager route: tie to `code=URBAN_OWNER_REQUIRED` + `event=urban.authz.compliance_alert` in observability runbook (8.5).
