# 13.5 — Wire wizardHost hooks in Denali create client

> **DEC:** DEC-P13-007  
> **Status:** DONE — 2026-06-18  
> **Parent:** [Phase 13 README](../README.md) · requires [13.4 create-page-split](13.4-create-page-split.md)

## Problem

`denali-create-tour-wizard-client.tsx` still calls package exports directly (`createDenaliWizardDraftSessionId`, `denaliPrepareDraftEnvelope`, `normalizeDenaliRemoteEnvelope`) although Phase 13.0b added equivalent `wizardHost` hooks on the Denali plugin.

## Solution

Web helper `wizard-draft-envelope-hooks.ts` delegates to `plugin.wizardHost`. **No `@app-tour/workspace-denali` import** in the helper (Phase 13.8 boundary fix). Denali callers inject package fallbacks:

| Concern | Hook | Fallback (injected by Denali caller) |
|---------|------|--------------------------------------|
| Session id | `wizardHost.media.createAssetSessionId()` | `createDenaliWizardDraftSessionId()` |
| Prepare envelope | `wizardHost.prepareDraftEnvelope` | `denaliPrepareDraftEnvelope` |
| Normalize remote | `wizardHost.normalizeRemoteEnvelope` | `denaliHydrateDraftEnvelope` |

```typescript
prepareWizardDraftEnvelope(plugin, form, meta, denaliPrepareDraftEnvelope);
normalizeWizardRemoteEnvelope(plugin, envelope, (env) =>
  denaliHydrateDraftEnvelope(env, env.form, env.meta));
```

**Unchanged in 13.5:** `isDenaliFreshStartEnvelope` for OCC bypass · `mergeDenaliWizardDraftEnvelope` (web merge module).
