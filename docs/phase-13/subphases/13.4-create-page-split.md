# 13.4 — Create tour page split (Denali vs workspace shell)

> **DEC:** DEC-P13-006  
> **Status:** DONE — 2026-06-18  
> **Parent:** [Phase 13 README](../README.md)

## Problem

`new-tour-wizard-client.tsx` (~920 lines) mixes Denali draft sync, clone/preset orchestration, and generic starter/urban create behind ~45 `isDenali` branches. Blocks plugin-neutral closure and 13.5 hook wiring.

## Solution

Mechanical split (COPY then TRIM — no logic rewrites):

| File | Role |
|------|------|
| `new-tour-wizard-client.tsx` | Thin router by `session.pluginId` (< 30 lines) |
| `denali-create-tour-wizard-client.tsx` | Denali draft + clone + preset + submit (no `isDenali`) |
| `workspace-create-tour-shell.tsx` | Starter/Urban local draft + simple `createTourAction` |

Pattern mirrors `tour-edit-page-client.tsx` → `DenaliFlatEditPageClient`.

## Router

```typescript
export function NewTourWizardClient() {
  const session = useAppSession();
  if (session.pluginId === "denali") {
    return <DenaliCreateTourWizardClient />;
  }
  return <WorkspaceCreateTourWizardShell />;
}
```

## Preserved

- Default export name `NewTourWizardClient` for `page.tsx`
- All `data-testid` constants unchanged
- `data-new-tour-wizard` root attribute
- `createDenaliWizardDraftSessionId()` direct import (13.5 wires `wizardHost.media`)
