# 13.2 — BFF wizard media path (neutral route + alias)

> **DEC:** DEC-P13-004  
> **Status:** DONE — 2026-06-18  
> **Parent:** [Phase 13 README](../README.md) · requires [13.1 api-wizard-media-dispatch](13.1-api-wizard-media-dispatch.md)

## Problem

Web upload client hardcodes `/api/tours/wizard-photos`. `mediaRouteKey` on `WorkspaceWizardMediaHooks` is unused on the web tier. Future workspaces need a **plugin-neutral BFF** without breaking Denali bookmarks and E2E probes.

## Solution

| Layer | Change |
|-------|--------|
| **Neutral BFF** | `POST /api/wizard-media/[mediaRouteKey]` · `GET …/url` |
| **Legacy alias** | `/api/tours/wizard-photos` (+ `/url`) delegate to shared proxy |
| **Helper** | `resolveWizardMediaBffPath(mediaRouteKey)` — Denali `"wizard-photos"` → legacy path until callers opt into neutral URL |
| **Upload client** | Optional `mediaRouteKey` param; fetch via helper (default unchanged) |

Shared proxy: `proxy-wizard-media-api.server.ts` maps `mediaRouteKey` → API backend paths (`/tours/wizard-photos` today).

```typescript
// resolve-wizard-media-bff-path.ts
const MEDIA_ROUTE_KEY_TO_BFF: Record<string, string> = {
  "wizard-photos": "/api/tours/wizard-photos",
};

export function resolveWizardMediaBffPath(mediaRouteKey: string): string {
  return MEDIA_ROUTE_KEY_TO_BFF[mediaRouteKey] ?? "/api/tours/wizard-photos";
}
```

```typescript
// resolve-wizard-media-backend-path.ts (server-only)
const MEDIA_ROUTE_KEY_TO_BACKEND = {
  "wizard-photos": {
    upload: "/tours/wizard-photos",
    signedUrl: "/tours/wizard-photos/url",
  },
} as const;
```

## Header contract (unchanged)

- Upload: `X-Wizard-Session-Id`, `X-Photo-Id`, `Content-Type`
- Signed URL: `storageKey` query param
- Auth: session cookie → `Authorization: Bearer` to API
