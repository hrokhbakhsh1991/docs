# 13.0 — Workspace wizard media contract (SDK)

> **DEC:** DEC-P13-001  
> **Status:** DONE — 2026-06-18  
> **Parent:** [Phase 13 README](../README.md)

## Problem

Denali wizard photo upload uses a **provisional session id** (`wizardSessionId`) and BFF path `/api/tours/wizard-photos`, but:

- Session creation is hardcoded in `new-tour-wizard-client.tsx` via `createDenaliWizardDraftSessionId()` from the Denali package.
- API routes gate on `workspaceType !== "denali"` instead of a plugin capability.
- No SDK contract describes which workspaces support wizard-scoped async asset upload.

Phase 13.0 adds **`WorkspaceWizardMediaHooks`** on `WorkspaceWizardHostHooks` — types + Denali reference impl only. **No route, BFF, or upload behavior changes in 13.0.**

## Solution

```typescript
export type WorkspaceWizardMediaHooks = {
  readonly createAssetSessionId: () => string;
  readonly isAssetSessionId: (value: string) => boolean;
  readonly mediaRouteKey: string;
};
```

Attached as optional field on existing hooks:

```typescript
export type WorkspaceWizardHostHooks = {
  // …existing Phase 12 hooks…
  readonly media?: WorkspaceWizardMediaHooks;
};
```

Workspaces without async assets omit `media` (Urban, Starter).

## Interface semantics

| Member | Contract |
|--------|----------|
| `createAssetSessionId()` | Returns a **UUID v4** string. Used as MinIO path segment `{tenantId}/wizard-drafts/{sessionId}/photos/{photoId}`. Must be stable for the wizard mount lifetime. |
| `isAssetSessionId(value)` | Returns true only for ids this workspace would mint. Denali: RFC 4122 UUID regex (matches API header validation). |
| `mediaRouteKey` | **Opaque** key for web BFF resolution — not an API URL. Denali: `"wizard-photos"` → `/api/tours/wizard-photos` until Phase 13.2 adds workspace-scoped routes. |

### Error codes (unchanged in 13.0)

Product-neutral codes already used by API + web (see `docs/phase-6/subphases/6.7-minio-photos.md`):

- `PHOTO_STORAGE_FULL` (507)
- `PHOTO_STORAGE_UNAVAILABLE` (503)
- `WIZARD_PHOTO_*` / `DENALI_PHOTO_*` validation

13.0 does **not** move error mapping into SDK.

### Engine ingress

`wizardHost` is stripped before `PlatformWizardEngine.create` (same as Phase 12). `media` hooks are **web-only** — not passed to platform-core validation.

## Denali reference implementation

File: `packages/workspaces/denali/src/wizard/denali-wizard-host-hooks.ts`

```typescript
import {
  createDenaliWizardDraftSessionId,
  isDenaliWizardDraftSessionId,
} from "../photos/wizard-draft-session-id";

media: Object.freeze({
  createAssetSessionId: createDenaliWizardDraftSessionId,
  isAssetSessionId: isDenaliWizardDraftSessionId,
  mediaRouteKey: "wizard-photos",
}),
```

Delegates to existing functions in `packages/workspaces/denali/src/photos/wizard-draft-session-id.ts` — **no new session algorithm**.

## Migration path for `wizardSessionId`

| Phase | Web / API change |
|-------|------------------|
| **13.0 (this)** | SDK + Denali `wizardHost.media` only. Page still calls `createDenaliWizardDraftSessionId()` directly. |
| **13.4–13.5** | `DenaliCreateTourWizardClient` reads `plugin.wizardHost.media.createAssetSessionId()` with fallback to package export. |
| **13.1–13.2** | API dispatch via manifest; BFF may add `/api/workspaces/[id]/wizard-assets` with alias for `wizard-photos`. |
| **13.7** | Optional object key prefix `{pluginId}/wizard-drafts/…` |

Envelope meta field name stays `wizardSessionId` in `DenaliWizardDraftMeta` — workspace-specific schema, not SDK-mandated.

## Examples

### Denali plugin (after 13.0)

```typescript
const plugin = getDenaliWorkspacePlugin();
const sessionId = plugin.wizardHost?.media?.createAssetSessionId();
// → UUID, same as createDenaliWizardDraftSessionId()
```

### Urban / Starter (no media)

```typescript
const plugin = getUrbanWorkspacePlugin();
assert.equal(plugin.wizardHost?.media, undefined);
```

### Future web upload client (13.2+)

```typescript
const media = plugin.wizardHost?.media;
if (media == null) throw new Error("WORKSPACE_MEDIA_NOT_SUPPORTED");
const path = resolveWizardMediaBffPath(media.mediaRouteKey);
// fetch(path, { headers: { "X-Wizard-Session-Id": sessionId, ... } })
```
