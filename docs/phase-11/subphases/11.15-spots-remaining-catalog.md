# Subphase 11.15 — Marketing `spotsRemaining`

> **Authority:** [`docs/workspaces/denali/public-catalog.md`](../../workspaces/denali/public-catalog.md) · **DEC-P11-013**

## Goal

Expose **public-safe** seat availability on Denali catalog cards so `apps/marketing` can show remaining capacity without operator booking PII.

## Public-safe aggregation

| Input | Rule |
| ----- | ---- |
| `totalCapacity` | `canonical.data.capacityMax` (existing) |
| Occupied seats | Sum of `partySize` for bookings with `status === "approved"` only |
| `spotsRemaining` | `max(0, totalCapacity - occupied)` when capacity known; `null` when `totalCapacity` is unknown |

**Excluded from occupancy:** `pending`, `waitlisted`, `rejected`, `cancelled` — no guest labels, emails, or payment fields in catalog responses.

## Port

`DenaliPublicBookingPort.sumApprovedPartySizeByTourIds(tenantId, tourIds)` — host implements via `apps/api` bookings repository (RLS-scoped).

Catalog list/detail handlers enrich `toDenaliCatalogCard` output after mapping.

## Contract

| Field | Type | Notes |
| ----- | ---- | ----- |
| `spotsRemaining` | `number \| null` | Optional on `PublicCatalogCard`; Denali catalog always sets when enriching |
