# Subphase 11.13 — Clone photo remint

> **Authority:** [`tour-clone-hydration.md`](../tour-clone-hydration.md) · **DEC-P11-011**

## Problem

Tour duplicate copied canonical photo rows verbatim — same `id` and `storageKey` (`{tenant}/tours/{sourceTourId}/photos/{photoId}`). Wizard preview only signs `wizard-drafts/` keys; cloned blobs stayed bound to the source tour.

## Decision

| Flow | Canonical | Storage |
| ---- | --------- | ------- |
| `?clone=` wizard | New UUID per row; `storageKey` → `wizard-drafts/{sessionId}/photos/{newId}` | `POST /tours/clone-photo-remint` copies MinIO objects |
| `POST /tours/{id}/clone` | Remint after create with `tours/{newTourId}/photos/{newId}` | Inline in `ToursService.cloneTour` when MinIO configured |

URL-only photos (`https://…`) keep `url`; only `id` is reminted.

## Contract

### `remintDenaliClonePhotosInCanonical`

`packages/workspaces/denali/src/clone/remint-denali-clone-photos.ts`

Returns `{ data, plan }` where `plan` entries are `{ sourceStorageKey, destStorageKey, oldPhotoId, newPhotoId }`.

### `POST /tours/clone-photo-remint`

| Item | Value |
| ---- | ----- |
| Auth | Operator session (Denali tenant) |
| Body | `{ plan: DenaliPhotoRemintPlanEntry[] }` |
| Success | `204` |
| MinIO missing | `503 MINIO_NOT_CONFIGURED` |

Keys must be tenant-scoped; destination must be under `wizard-drafts/` for this endpoint.

### SDK

`TourCloneHydrationInput` gains optional `wizardSessionId` + `tenantId`.  
`TourCloneHydrationResult` gains optional `photoRemintPlan`.

## Web wiring

After `hydrateWizardDraft` with remint plan, `new-tour-wizard-client` calls BFF `POST /api/tours/clone-photo-remint` before `setData`.

## Acceptance

| ID | Assertion |
| -- | --------- |
| DENALI-P11-13-01 | Remint assigns new UUIDs; storageKey uses wizard-draft prefix |
| DENALI-P11-13-02 | URL-only rows keep https url |
| API-P11-13-01 | clone-photo-remint rejects non-wizard dest keys |
| API-P11-13-02 | Server clone remints tour photo keys when MinIO configured |
