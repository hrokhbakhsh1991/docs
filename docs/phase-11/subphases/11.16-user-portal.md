# Subphase 11.16 — User Portal (`apps/portal`)

> **Authority:** MAP §3.5 · [`public-catalog.md`](../../workspaces/denali/public-catalog.md) · **DEC-P11-014** · **P4-B closure:** [`platform-portal-registration.mdoc`](../../phase-17/platform-portal-registration.mdoc) · **P6 host parity:** [`p6-host-addressing-architecture.mdoc`](../../phase-19/p6-host-addressing-architecture.mdoc)

## Goal

Introduce **`apps/portal`** — guest shell for public catalog registration + member `/me` (P6-3) — so `apps/web` remains operator-focused.

## Scope (11.16 + P6 extensions)

| In scope                                 | Out of scope (later)                 |
| ---------------------------------------- | ------------------------------------ |
| Next.js shell on dev port **3003**       | Operator wizard / tour create        |
| `GET /catalog/{tourId}/register`         | Full session hydration into wizard   |
| Public-auth BFF (`/api/public-auth/*`)   | `apps/admin-panel`                   |
| Registration intake BFF → workspace HTTP | Cookie domain across prod subdomains |
| Marketing CTA → portal base URL          | Cross-club SSO                     |
| **P6-3:** `/me/registrations` + receipt  | Full account settings portal         |

## Dev topology (P6 canonical)

| App              | Port | Canonical dev host              | Legacy smoke alias        |
| ---------------- | ---- | ------------------------------- | ------------------------- |
| `apps/web`       | 3000 | `{club}.admin.localhost`        | `{club}.localhost:3000`   |
| `apps/marketing` | 3002 | `{club}.localhost`              | `shop.{club}.localhost`   |
| `apps/portal`    | 3003 | **`{club}.portal.localhost`**   | `{club}.localhost:3003`   |

CTA bridge: `buildDevPortalPublicBaseUrl` (`@app-tour/tenant-kernel`) — see P6-0.

Env overrides: `PORTAL_PUBLIC_BASE_URL`, `PORTAL_DEV_PORT`, `MARKETING_PUBLIC_BASE_URL`.

## Backward compatibility

`apps/web` `/catalog/{tourId}/register` **redirects** to portal URL (no duplicate flow).
