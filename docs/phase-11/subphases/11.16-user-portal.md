# Subphase 11.16 — User Portal (`apps/portal`)

> **Authority:** MAP §3.5 · [`public-catalog.md`](../../workspaces/denali/public-catalog.md) · **DEC-P11-014**

## Goal

Introduce **`apps/portal`** — protected guest shell for public catalog registration — so `apps/web` remains operator-focused and marketing can link to a dedicated User Portal origin.

## Scope (11.16)

| In scope | Out of scope (later) |
| -------- | -------------------- |
| Next.js shell on dev port **3003** | Operator wizard / tour create |
| `GET /catalog/{tourId}/register` | Full session hydration into wizard |
| Public-auth BFF (`/api/public-auth/*`) | `apps/admin-panel` |
| Registration intake BFF → workspace HTTP | Cookie domain across prod subdomains |
| Marketing CTA → portal base URL | E2E smoke migration from web |

## Dev topology

| App | Port | Role |
| --- | ---- | ---- |
| `apps/web` | 3000 | Operator shell |
| `apps/marketing` | 3002 | Public catalog SEO |
| `apps/portal` | 3003 | Guest registration intake |

Host map mirrors web: `denali.localhost:3003`, `urban.localhost:3003`, `operator.localhost:3003`.

Marketing `shop.{label}.localhost:3002` links registration to `{label}.localhost:3003/catalog/{tourId}/register`.

Env overrides: `PORTAL_PUBLIC_BASE_URL`, `PORTAL_DEV_PORT`.

## Backward compatibility

`apps/web` `/catalog/{tourId}/register` **redirects** to portal URL until operator routes drop the public catalog group entirely.

## Implementation map

| File | Role |
| ---- | ---- |
| `apps/portal/package.json` | `@apps/portal` workspace |
